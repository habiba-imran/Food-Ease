# FoodEase UI polish — 7 November 2026

The existing centered editorial hero, original burger photograph, condensed heading font, section order, product cards, category strip, and menu organization are retained. The hero now reads **FULL OF FLAVOURS.** with separate space for the headline and photograph. Its forest-green gradient follows the requested direction; the pale-green, beige, and orange catalog palette remains.

## Changes

- Removed Campaign, Inspect 3D, rotation, separation and hero pause controls, their state/listeners, loader, inspector source, and generated inspector bundle. The separate tabletop preview still works through the existing application.
- Added restrained desktop floating (7-second easing, two cycles, at most 7px vertical travel and 1.5 degrees of tilt) and pointer parallax capped at 6px horizontally / 4px vertically. The flat image never turns around the Y axis. Touch/tablet layouts remain still; reduced motion and Calm motion disable decorative movement.
- Rebalanced headline, image, supporting copy, quiet orbit lines and CTA across breakpoints. Kept the original trapezoid CTA, improved hover/press/focus feedback and single-line labeling, and retained its existing manual-order/menu action.
- Refined the existing sticky header, navigation spacing, cart count and 44px minimum navigation targets. Removed the negative header margin so it no longer relies on overlapping the welcome area.
- Improved popular-card spacing and image hover, category alignment and selected-state contrast, and smooth horizontal category scrolling.
- Increased search/filter discoverability, readable prices and descriptions, consistent card bodies/action rows, and restrained card hover. Corrected responsive image sizing hints for the existing full-width menu. All 28 product image files load; none required replacement.
- Add feedback now confirms the authoritative cart-count increase with a temporary check mark. The cart badge still acknowledges changes. Removed the large flying-image effect and pointer-driven card tilting.
- Refined footer spacing and text sizes. On phones, the floating voice entry uses a compact 48px microphone button with the existing accessible name so the hero heading remains clear. Voice dialogs retain the full label and existing behavior.

Product names, prices, descriptions, availability, categories, ordering authority, checkout and voice application code were not changed by this UI task. Pre-existing edits to app/voice/orchestration files were preserved. No dependencies were added; no deployment was performed.

### Existing voice failures

Three conversation tests expect page-reading/ordinal text; three opening tests expect specific chooser or mode-switch behavior; one voice-entry test expects an unclear-choice reply. All seven also failed with the original hero markup, original compiled stylesheet and original decorative JavaScript served through browser-only route overrides, while retaining the current application/worker code. The matching assertions and transcript/state differences are recorded in `artifacts/ui-polish-2026-11-07/baseline-voice-check.txt`. These failures remain outside the UI scope.

Repeated audits exhausted the disposable fixture's 128 shopping-session capacity. The fixture was restarted, and final focused tests and all seven baseline comparisons were rerun using fresh fixtures; capacity failures were not counted as baseline evidence.

### Limits

Browser tests use the repository's offline provider/RTC fixture. Live provider voice/audio quality, physical touch devices, human screen-reader testing and production deployment were not verified. The contrast audit excludes gradients, images, transparent foregrounds and disabled controls, so it is not a WCAG conformance claim.
